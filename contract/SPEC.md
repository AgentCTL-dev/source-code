# The Agent Control Contract — ACC 2

> **Baseline:** agentd **1.3.1** (the reference conformant agent). Supersedes the
> ACC 1.x / "contract 2.0" spec that anchored on `--capabilities` `surfaces{}` +
> `contract_version` negotiation — the rewritten agent emits neither (see §3).
> RFC 0026 §3 records the re-baseline; `VERSION` records the pinned clocks.
> **P0 unchanged:** agentctl depends only on this contract — never on the
> agent's code, and never by linking it (the reference implementation is AGPL).

## 1. Scope

ACC 2 is the complete wire-and-process surface agentctl drives an agent
through. Nine artifacts, each authoritative for its plane:

| Artifact | Governs |
|---|---|
| `schemas/config.schema.json` | the agent's config document (`config_version: "1"`); generated by `agentd --config-schema`; carries **`x-agentd-contract-version`** — the config-contract clock |
| `schemas/workflow.schema.json` | the workflow dialect (`workflow-3`); generated by `agentd --workflow-schema` |
| `schemas/exit-codes.table.json` | process exit codes + the frozen `pod_failure_intent` mapping (`exit_codes 1.0`) the operator compiles into `podFailurePolicy` |
| `schemas/env-convention.json` | env/flag derivation, alias families, precedence, renderer rules |
| `schemas/metrics.registry.json` | Prometheus surface (`metrics_schema 1.2`) with the live/reserved/child-local split |
| `schemas/a2a.profile.json` | the A2A listener: methods, admin verbs, command ops, principals, errors, TLS caveats |
| `schemas/store.profile.json` | the store-over-MCP **checkpointer profile** the managed state service implements |
| `schemas/restart-only.json` | the reload/restart config partition the operator's diff classifier uses |
| `schemas/manifest.schema.json` | `--capabilities` (informational only — §3) |

Fixtures: `fixtures/capabilities/agentd-1.3.1-{default,configured}.json`
(real captures), `fixtures/config/full-featured.yml` (a known-valid config
exercising schedule / webhook / subscribe / a2a-command / stream starts —
`--validate-config` exit 0 is asserted by conformance), and
`fixtures/config/services-{catalog,instance}.json` +
`effective-server.ndjson` — the two-layer catalog invocation with the
binary's REAL `config.effective_server` resolution captured (allow narrowed
by the consumer, tags inherited from the catalog; 2026-08-30, agentd 1.3.1).

## 2. The process contract

- **Invocation** is config-document based: `agentd -c <file> [-c <file>…]`
  (layers merge RFC 7396: objects merge, **lists replace**), plus the
  conventional folders (`workflows/ skills/ subagents/ context/`) beside the
  LAST config file only (upstream configuration.md §folders — a services.yaml
  layered before agentd.yml contributes no folders), adopted only-when-absent. Flags are reserved for process intent
  (`--metrics-addr`, `--drain-timeout`, probes). The 1.x execution-mode and
  clustering flags (`--mode`, `--shard`, `--claim`, `--subscribe`, …) are
  **removed upstream and exit 2** — nothing may render them.
- **Validation authority** is the binary: `agentd --validate-config` runs the
  exact startup checks, network-offline, exit 0/2; stderr is NDJSON
  (`config.valid` / errors; `config.effective_server` lines when a `services:`
  catalog is present). Admission shells this, never re-implements it.
  Verified boundaries (2026-08-30, upstream-confirmed): workflow `file:` refs
  are stat'd; TLS/CA/store paths are NOT; `{{secret:…}}` refs must resolve
  from env **only in header maps** (`intelligence.headers`, MCP/webhook
  headers/auth) — `intelligence.token` and `mcp.servers[].auth.token` pass
  UNRESOLVED (upstream defect raised; do not depend on either behavior:
  export placeholders for every ref, and check Secret existence separately).
  Same family (verified 2026-08-30): `a2a.principals[].match.bearer_ref` is
  NOT checked by `--validate-config` but IS resolved at startup (config.invalid,
  exit 2 on a dangling ref) — the operator must land the referenced Secret
  material BEFORE any pod mounts the document. A bearer_ref without `{{` is
  used VERBATIM as the credential; generators must refuse the literal form.
- **A2A auth composition** (verified 2026-08-30, upstream-confirmed): setting
  `a2a.tls.client_ca` makes a CA-signed client certificate MANDATORY for every
  connection (no unauthenticated fallback in the verifier) — a bearer-only
  caller cannot even complete the handshake, despite agentd's own validation
  message suggesting client_ca/bearer/pairing combine freely ("and/or";
  upstream doc defect raised). Principal rules are FIRST-match-wins in listed
  order: per-user bearer rules must precede the control-plane operator
  san-rule, and any non-empty `a2a.principals` list disables the implicit
  management/loopback operator fallback entirely.
- **Exit codes** per `exit-codes.table.json`; a clean drain is 0, never 143;
  the drain worst case (drain_timeout 25 s + abandon 3 s = **28 s**) must stay
  below `terminationGracePeriodSeconds`.
- **Identity**: `agent.name` (via `AGENT_POD_NAME` downward API) is the durable
  store fence — unique per replica, never shared; a store seq-CAS conflict is a
  split-brain alarm, not a retry.
- **Lifecycle**: `lifecycle.run_until` is always rendered **explicitly**
  (`drained` for daemons, `idle` for jobs) — `auto` misclassifies webhook/
  stream-only instances (upstream ask U4).

## 3. Version negotiation (what replaced `surfaces{}`)

`--capabilities` at 1.3.1 emits `{runtime, version, …}` with **no
`contract_version` and no `surfaces{}`**, and under-reports several planes
(webhooks absent; `start_kinds` missing webhook/stream; `lifecycle.daemon`
unreliable; skills partially reported) — upstream asks U3/U4. ACC 2 therefore
anchors on **four independent clocks**, each read from its own artifact:

1. `x-agentd-contract-version` in the served config schema (`"1.0"`) — the
   config-document contract;
2. the workflow schema `$id` (`…/workflow-3.json`) — the dialect;
3. `exit_codes` (`"1.0"`) — vendored from `exit.rs`, asserted by conformance
   behavior tests, since the binary does not yet surface it;
4. `metrics_schema` (`"1.2"`) — likewise vendored + behavior-asserted.

Rules: a **major** the client does not recognize on any clock ⇒ refuse to
manage that agent version (surface `ContractSkew` on the CR). A newer *minor*
is acceptable (additive). `--capabilities` is used for what it is reliable
for: agent `version` identification, configured-listener echo, admin-verb and
builtin-command inventories — never as the shape/trigger oracle.

## 4. Conformance

`fixtures/` are captured from the pinned binary; CI re-captures schemas from
the same binary version and **diffs against the vendored copies** (drift ⇒
red). Behavior conformance (agentctl-e2e): exit-code table spot checks,
validate-config authority, checkpointer-profile round trip incl. CAS conflict
and SIGKILL/restore, drain-is-zero, A2A admin verbs, principal roles. The
renderer's own outputs must pass `--validate-config` for every rendering test
fixture.

## 5. Known upstream gaps this contract works around

Tracked in `docs/v2/PLAN.md` §Upstream: U1 reload verb / ConfigMap-watch
verification (until then: config changes ⇒ rolling restart), U2 A2A TLS
hot-rotation (until then: cert renewal ⇒ rolling restart), U3 manifest
surfaces, U4 `run_until: auto` + long-lived-list unification, U5 published
schema `$defs` drift (why the vendored schema is regenerated from the binary,
not fetched from agentd.dev).
